# Versioned synthetic TLS golden sources (TLS-401)

Canonical assets and hashes are maintained in
[`native_build/verification/tls/fixtures/manifest.json`](../../../../../native_build/verification/tls/fixtures/manifest.json).
The manifest is data; its separate schema is `native_build/verification/tls/fixture-manifest.json`.

| Fixture | Protocol | PCAP source | Secrets |
|---|---|---|---|
| `tls12-h1` | TLS 1.2 / HTTP/1.1 | Own host loopback, Python SSL client/server | Same connection plus independent wrong connection |
| `tls13-h1` | TLS 1.3 / HTTP/1.1 | Own host loopback, Python SSL client/server | Same connection plus independent wrong connection |
| `tls13-h2` | TLS 1.3 / HTTP/2 | Own host loopback, Python SSL + hyper-h2 | Same connection plus independent wrong connection |
| `tls12-h2` | TLS 1.2 / AES-128-GCM / HTTP/2 | OpenSSL memory BIOs, synthetic IPv4/TCP | Downstream TLS A + upstream TLS B |
| `tls13-chacha-h1` | TLS 1.3 / ChaCha20-Poly1305 / HTTP/1.1 | Same controlled BIO relay | TLS A + TLS B |
| `tls13-chacha-h2` | TLS 1.3 / ChaCha20-Poly1305 / HTTP/2 | Same controlled BIO relay | TLS A + TLS B |
| `tls13-hrr-h1` | TLS 1.3 / AES-128-GCM / HRR / HTTP/1.1 | P-256 server, initial X25519 client key share | TLS A + TLS B |
| `tls13-keyupdate-h1` | TLS 1.3 / AES-128-GCM / KeyUpdate / HTTP/1.1 | Both peers update before response | TLS A + TLS B |

All eight return only `LayerAnalyzer TLS fixture v1\n` (UTF-8, 29 bytes), SHA-256
`9b1ce3253f3312a2d0f896f307a944a2effe972d55ba1a33cc939feb6e6fd7c4`.
The fixed input body is compared to actual tshark dissection and independently
parsed client responses. No real user traffic or runtime private key is included;
the public test keylogs apply only to the public captures. Key direction is
`direct-test-connection` for the original three. For the five additions, the test
driver relays actual application bytes between two separately verified OpenSSL
TLS pairs. `session.keys` belongs to A, `wrong.keys` belongs to B, and
`upstream.pcap` proves B's keys decrypt B but never A. This controlled BIO relay
does not exercise the production VPN/Go proxy. Its PCAP is explicitly labeled
`synthetic-tcp-serialization`; neither source is Android TUN evidence.

Certificates are generated at runtime; offline assets include only the public CA.
Live tests must use freshly generated certificates and explicit test-root trust.
HTTP/2 uses hyper-h2 4.3.0 (MIT), with its HPACK/frame dependencies; certificate
generation uses cryptography 46.0.3 (Apache-2.0/BSD). These host Python packages are
installed separately, not vendored or shipped in the application. tshark/dumpcap
3.6.0 (GPL-2.0-or-later) are installed host tools, not distributed by this change.
The synthetic bytes were generated by this project's fixture scripts, not copied
from third-party captures. See fixture README/manifest for commands and exact hashes.

Every fixture includes zeroed secrets with the correct client random, a capture
without ClientHello records (including HRR retry), and a capture missing a TCP
segment identified by the actual response body dissection. The five additions
also include unknown-root and wrong-hostname rejection captures. The generator
uses `SSL_VERIFY_PEER` plus hostname verification; the manifest records the real
nonzero OpenSSL verification result. Those captures assert absence of application
data; they do not substitute for Android's production trust matrix (TLS-402).

`stageTlsFixtureAssets` now always stages the manifest and its 87 referenced files
under `tls/fixtures/` in **the test APK only**. `TlsGoldenSuiteTest` uses production
JNI with probe OFF, reads `InstrumentationRegistry.getInstrumentation().context.assets`,
checks every SHA-256 through `TlsPassiveFixture`, and deletes copied inputs after
closing native sessions. Hash-only results go to the target app's
`getExternalFilesDir(null)/tls-suite-v1/<runId>/` so adb can collect them even on OEMs
that disable `run-as`. These reports contain only fixture hashes/status; PCAP/keylog
inputs stay in noBackupFilesDir and are deleted after use. No canonical files are duplicated in source control.

The manifest locks `suiteVersion=tls-golden-v1`, desktop tshark **3.6.0** and embedded
Wireshark **4.0.10**. The offline suite does not exercise live VPN forwarding.
Run `native_build/verification/tls/run_suite.ps1`; see the fixture README for parameters.
