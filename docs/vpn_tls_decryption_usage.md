# TLS 解密

LayerAnalyzer 可以用端点提供的 NSS 密钥日志分析已有抓包，也可以在 VPN 抓包时对选定范围启用本地 TLS 代理。请只分析自己拥有或获授权的应用和连接。安装包默认包含代理引擎，**不会默认开启代理或安装 CA**。

## 已有 PCAP / PCAPNG：不需要安装 CA

1. 打开抓包，选择「更多文件操作 → TLS 密钥日志 → 导入密钥日志」，选择与这些连接匹配的 NSS key log。CA 证书不能用于回溯解密历史抓包。
2. 等待重新解析。「已配置密钥」只表示已加载文件；在帧详情切换到派生 TLS 字节，或长按报文选择「跟踪 TLS 流」，确认是否实际得到明文。错误的密钥、缺少握手、丢包或缺失分段都可能导致无法解密。
3. 「清除分析密钥」清除本次解析配置，不改写原始抓包；重新打开外部文件时需要重新导入。可以用仓库的[合成测试抓包和配套密钥](../native_build/verification/tls/fixtures/README.md)练习，不要安装夹具 CA。

## VPN 抓包：只代理选中的范围

1. 在「VPN 应用流量快照」选择获授权的测试应用。打开「对所选范围解密 TLS」，选择「仅下列域名」，添加主机名和候选 TCP 端口（默认 443）。空域名列表不解密任何域名；绕过规则优先。`*.example.test` 不匹配根域 `example.test`。
2. 在「证书设置」生成本地 CA，核对指纹后导出并安装**公钥证书**。Android 11 及以上需从系统安全设置手工安装。安装不保证目标应用信任用户 CA；源站证书也必须通过设备系统信任库和主机名校验。请勿关闭上游校验。
3. 如果需要稍后重开会话，开启「保留本次抓取的会话密钥」。点「开始」并授权 VPN，再让测试应用发起**新的 TCP 连接**。查看「TLS 连接」区分已代理、已保存密钥和已验证可解密；代理成功本身不是明文证据。
4. 点「停止」，等待写盘完成，通过「打开已保存文件」打开整个会话。原始 TUN 报文保持加密，分析器使用与下游连接匹配的密钥解密。重置 CA 不会恢复丢失的密钥。结束测试后，从系统的用户受信任凭据中核对指纹并移除 CA；卸载应用不会代为移除。

## 支持边界与导出

- 主动代理限于 TCP 上从连接起始协商的 TLS 1.2/1.3。支持 HTTP/1.1、HTTP/2；TLS Follow 是整条连接的字节流（可包含过滤范围外的帧），不是单个 HTTP/2 请求。
- 不主动解密 QUIC/HTTP3、DTLS、STARTTLS 或嵌套 TLS；不绕过证书固定，不保证 ECH、mTLS 或 PSK。可选的「阻止 UDP/443」也会丢弃该端口上的非 QUIC 流量，且不保证应用回退到 TCP。未捕获的 IPv6 流量不在代理范围内。
- 默认导出原始抓包，不附带会话密钥。「完整可解密会话包」要求完整会话、匹配密钥、清除过滤器及单独同意。持有者可能解密同一连接上的其他请求。只需局部内容时，单独选择并确认导出相应流、字节或 HTTP 对象。
- 会话密钥和明文可能暴露凭据、Cookie 和个人数据。不要附在普通问题报告中；导出到其他位置的副本需要自行删除。启用 TLS 抓包不等于允许把解密内容发送到 AI 服务。
